# Lab 06: Registry and Discovery (Pattern 5)

**Package:** `labs/lab06-registry-discovery` → import `lab06_registry`
**Profile:** `lab06`
**Models:** `quick` (agents), `decision` (candidate selection)
**Frameworks:** a2a-sdk (+ `signing` extra), Strands, ADK, LangGraph

> **Pattern 5:** Discover agents through well-known cards, a curated registry or injected trusted cards, and **delegate only after verification**.

## 1. Learning objectives

1. Know the three discovery strategies in the spec (§8):
   - **Well-known URI:** `GET https://host/.well-known/agent-card.json`.
   - **Curated registry:** a catalog service that returns cards by query.
   - **Direct configuration:** trusted cards injected from config or files.

   Know the trade-offs of each.
2. **Sign** Agent Cards with JWS (RFC 7515) over JCS-canonicalized JSON (RFC 8785), excluding `signatures`, using `a2a.utils.signing` [VERIFY API: sign/verify helpers]. Publish the public keys as a JWKS.
3. **Verify** before delegating: check the signature against a **trust store** (not against keys fetched from the same untrusted host), and enforce name/domain binding, freshness and capability expectations.
4. Detect and refuse a **rogue** agent: unsigned, signed by an untrusted key, tampered after signing, or impersonating a trusted name.
5. Choose among several verified candidates with the decision model.
6. Use the **extended card** after authentication to get private skills (a brief preview of Lab 10).

## 2. Services

| Service | Port | Description |
|---|---|---|
| `lab06-registry` | 10601 | **Curated registry** (FastAPI). `# CUSTOM`: the spec describes curated registries but defines no registry API. This one follows the spec's guidance and stores **cards, not just URLs**. |
| `lab06-agent-a` | 10602 | "Translator A" (Strands, quick). Card **signed** with key `lab06-a` (trusted). |
| `lab06-agent-b` | 10603 | "Translator B" (ADK, quick). Card **signed** with key `lab06-b` (trusted). Supports more languages, per its skills. |
| `lab06-agent-rogue` | 10604 | "Translator A" impersonator (a2a-sdk). Mode set by env `ROGUE_MODE=unsigned|untrusted_key|tampered|name_spoof`; the notebook switches it via a control endpoint `POST /_rogue/mode` (`# CUSTOM`, lab-only). |
| `lab06-delegator` | 10605 | LangGraph agent that discovers via the registry, verifies, selects with Nimble, then delegates. Served over A2A. |

Keys:
- `config/registry/keys/` holds dev keys (`lab06-a.private.jwk`, `lab06-b.private.jwk`, `rogue.private.jwk`), generated by `scripts/gen_lab06_keys.py` at build time if missing. The private keys are **git-ignored**.
- `config/registry/trust_store.json` holds the trusted public JWKs and bindings:

```json
{
  "trusted_keys": [
    {"kid": "lab06-a", "jwk": {...public...}, "allowed_names": ["Translator A"], "allowed_hosts": ["lab06-agent-a"]},
    {"kid": "lab06-b", "jwk": {...public...}, "allowed_names": ["Translator B"], "allowed_hosts": ["lab06-agent-b"]}
  ],
  "require_signature": true,
  "max_card_age_s": 86400
}
```

Agents sign their card at startup (`sign_card(card, private_jwk, kid)`) and add it to `card.signatures`. They serve `/.well-known/jwks.json` for completeness. The notebook explains why the verifier uses the **trust store** instead of fetching the JWKS from the same host: a host that controls both the card and the key proves nothing.

## 3. Registry API (`lab06-registry`)

| Method/Path | Behavior |
|---|---|
| `POST /agents` `{url}` | Fetch the card from `url` + well-known path. Verify it (see §4). Store `{id, url, card_json, verified, verification_report, fetched_at, etag}`. Registration of a card that fails verification is stored **quarantined** (`verified=false`) and never returned by default. |
| `GET /agents?skill=&tag=&q=&include_unverified=false` | Search over skill ids, tags and descriptions (simple token match). Returns cards and verification status. |
| `GET /agents/{id}` | Card and report |
| `POST /agents/{id}/refresh` | Re-fetch with `If-None-Match` and re-verify |
| `DELETE /agents/{id}` | Remove |
| `GET /healthz` | |

- A background task re-verifies every 5 minutes and marks agents unhealthy when the card is unreachable.
- Seed: `config/registry/seed.yaml` lists the URLs to register at startup: agent-a, agent-b and rogue. The rogue is quarantined at startup.
- The registry also exposes itself as an A2A agent with a `find_agent` skill. This is an optional stretch exercise mirroring the a2a-samples pattern of an MCP/agent-based card registry.

## 4. Verification (`a2a_labs_common.a2a.trust.CardVerifier`)

```python
class VerificationReport(BaseModel):
    ok: bool
    checks: dict[str, bool]   # signature_present, signature_valid, key_trusted, name_bound, host_bound,
                              # interfaces_match_host, not_expired, capabilities_ok
    kid: str | None
    reasons: list[str]

class CardVerifier:
    def __init__(self, trust_store: TrustStore): ...
    def verify(self, card: AgentCard, fetched_from: str) -> VerificationReport: ...

class VerifiedCardResolver:
    """Wraps a2a.client.A2ACardResolver: resolve → verify → raise UntrustedAgentError if not ok."""
```

Checks:
1. At least one signature is present.
2. The JWS verifies over the JCS-canonical card without `signatures`.
3. The `kid` is in the trust store.
4. `card.name` is in `allowed_names` for that kid.
5. The host of `fetched_from` and of every `supported_interfaces[].url` is in `allowed_hosts`.
6. Optional: `iat` in the protected header is no older than `max_card_age_s`.
7. Capabilities meet the caller's needs, e.g. streaming is required.

## 5. Delegator (`lab06-delegator`, LangGraph)

```text
START → search_registry(skill="translate") → verify_each (re-verify client-side! never trust registry blindly)
      → select [decision: choice among verified candidates, criteria = card descriptions + skills; plus "none"]
      → delegate (create_client(card) with the *verified* card object — injected, not re-fetched)
      → END
```

- Also demonstrates **direct configuration**: `DELEGATOR_INJECTED_CARDS=config/registry/injected/translator-b.json` loads a pre-verified card file and skips discovery.
- **Framework injection examples** (notebook cells, in-process):
  - **ADK:** `RemoteA2aAgent(name=…, agent_card=<AgentCard object or file path>)`, the injected trusted card [VERIFY that accepted types include an AgentCard object and a path].

  - **a2a-sdk:** `create_client(verified_card)`.

## 6. Notebook outline

1. Architecture and discovery strategies table: well-known, registry and direct, with trust model, freshness, scale and failure modes.
2. Setup.
3. **Well-known discovery**: fetch agent-a's card raw, show the `signatures` field and decode the JWS protected header (`alg`, `kid`).
4. **Sign and verify by hand**: canonicalize the card (JCS), show the bytes, verify with the trust-store key, then modify one character and watch verification fail.
5. **Registry**: list agents (rogue hidden), then `include_unverified=true` (rogue quarantined, with reasons).
6. **The rogue gallery**: switch `ROGUE_MODE` through each mode and re-register. Table of mode → failing check → reason. Highlight `name_spoof`: it is validly signed, but by the rogue key, and it claims the name "Translator A".
7. **Delegator flow**: "Translate 'good morning, how are you?' to Portuguese and Japanese". Show the search results, the client-side re-verification report, the Nimble choice probabilities over A vs B, and the delegation result.
8. **Injected trusted card**: the same delegation with registry discovery turned off.
9. **ADK, Strands and SDK injection** demos (in-process).
10. **Extended card teaser**: agent-b advertises `extended_agent_card=true`. Fetch it with its bearer token to see a private "legal translation" skill.
11. **Card refresh and ETag**: bump agent-b's card version (env + restart), then refresh in the registry. Show the old card replaced, and that the re-verification passed.
12. Grafana: `registry.verify_card` spans with `a2a.card.signature.valid=false` for the rogue.
13. Exercises:
    - (easy) add `allowed_hosts` wildcard support;
    - (medium) make the registry sign its search responses;
    - (stretch) expose the registry as an MCP server (`find_agent`) and use it from Lab 03's consumer.

## 7. Acceptance tests

- Unit:
  - sign/verify round trip;
  - tamper → invalid;
  - untrusted kid → `key_trusted=false`;
  - name spoof → `name_bound=false`;
  - host mismatch → `host_bound=false`.
- Integration:
  - the registry returns only A and B by default;
  - the rogue is quarantined in all 4 modes;
  - the delegator never contacts the rogue (assert no request in rogue logs via its `/_rogue/requests` counter);
  - the injected-card path works with the registry down.
